# VexTheater plan: add, remove and move tiles from the launcher

**Tier 3** (config schema change, new state file, many files). Follow CLAUDE.md: confirm
this plan, implement, verify, `reviewer` subagent, `bash scripts/preflight.sh`, commit
message. Written 2026-11-02 from a read of `src/config.rs`, `src/order.rs`,
`src/files.rs`, `src/window.rs`, `nix/module.nix`, `nix/package.nix`, README.md, and
vexos-nix `modules/htpc-theater.nix`.

## Context

Today every tile comes from `/etc/vextheater/config.json`, generated by vexos-nix
(`modules/htpc-theater.nix`), so adding Netflix or removing Plex means editing Nix and
rebuilding. The user wants to manage tiles from the TV:

- A **"+"** in the UI opens a list of services to add: Disney+, Netflix, Hulu, Peacock,
  and similar, plus any tile that was removed earlier.
- **Every tile** has options: **Move** and **Remove**. This includes tiles from the
  configuration. Anything removed can be added back later from "+".
- The **service catalog is built into VexTheater**, not sent by vexos-nix.
- **No scrolling:** when there are more tiles than fit on one row, they **wrap onto
  more rows** below. They never go off screen.

## Decisions (made in planning, keep unless the user says otherwise)

1. **State lives beside `order.json`**, in a new `~/.local/state/vextheater/tiles.json`,
   written with `files::write_json` (atomic) and read with `files::read_json`:
   ```json
   { "added": ["netflix", "disney-plus"],
     "hidden": { "main": [["Plex", 0]], "submenu:Games": [["Doom", 0]] } }
   ```
   - `added`: catalog ids, shown on the main row.
   - `hidden`: configured tiles the user removed, per page key, as `order::Identity`
     (name, occurrence), the same identity `order.rs` already uses.
   - Removing an added tile deletes its id from `added`. Removing a configured tile adds
     its identity to `hidden`.
   - The configuration stays read-only and the source of truth for configured tiles. A
     tile added to the config later appears as before; a hidden identity that no longer
     matches anything is ignored, like a stale order entry.
2. **Order:** added catalog tiles join the main page's names before `order::arrange`, so a
   new one goes last and can be moved like any other. Re-adding a hidden configured tile
   puts it back where `order.json` last had it. "Reset tile order" still resets only the
   order, not what is added or hidden.
3. **Name clashes:** a catalog entry whose name equals a configured main-row tile's name
   (e.g. vexos-nix's "YouTube") is not offered, so identities stay unique and the user
   never sees two "YouTube" tiles.
4. **Catalog:** a new `src/catalog.rs` holding a `const` list of web apps:
   `id`, `name`, `url`, `icon`, `description`, `tv_user_agent: bool`. Start with Netflix,
   Disney+, Hulu, Max, Peacock, Paramount+, Prime Video, Apple TV, YouTube (TV interface,
   `tv_user_agent: true`, `https://www.youtube.com/tv`), YouTube TV, Crunchyroll, Pluto TV,
   Tubi. Ids are stable once shipped (they're saved in `tiles.json`).
5. **Web apps launch the way vexos-nix's `mkWebApp` does** (port its logic to Rust;
   source: vexos-nix `modules/htpc-theater.nix`, `mkWebApp`):
   - profile dir `~/.local/share/vextheater/webapps/<id>` (`glib::user_data_dir()`),
     created if missing;
   - if `SingletonLock` is a symlink whose target, minus the trailing `-<pid>`, names a
     host other than this one, delete `SingletonLock`, `SingletonCookie`,
     `SingletonSocket` (Brave otherwise exits with no window after a hostname change);
   - if `Local State` is missing, write `{"brave":{"widevine_opted_in":true}}` so DRM
     plays on first launch;
   - run `<browser> --kiosk --app=<url> --user-data-dir=<dir>` plus
     `--user-agent=<smart-TV UA>` when `tv_user_agent`. Copy the UA string from vexos-nix
     `smartTvUserAgent`.
   - Launch through the existing `launch.rs` path for `Action::Command` (its own
     `systemd-run` scope, so home closes it), with each argument shell-quoted by the
     helper `launch.rs` already uses for desktop Exec lines. Do the profile preparation in
     Rust right before the launch.
6. **Browser:** new optional top-level config key **`browser`** (string: a path or a
   program name, run without a shell). When unset, use the first of `brave-origin`,
   `brave`, `brave-browser`, `google-chrome-stable`, `chromium` found on `PATH`.
   Chromium has no Widevine, so DRM services won't play there; the README should say so.
   With no browser found, catalog tiles are dimmed "Not installed", the same way
   `is_installed` already handles missing desktop and Flatpak apps.
7. **"+" button:** a round button with `list-add-symbolic` in the header, left of the
   power button, styled like it (`power-button` CSS class or a shared one). Up from the
   top tile row selects it; Left and Right move between "+" and power. It opens a new
   **Add** page. That page lists hidden configured tiles first (description "Put back on
   <page title>"), then the catalog entries not already shown. Choosing one adds it,
   saves `tiles.json`, rebuilds the affected page, returns to the main row, and selects
   the new tile. With nothing to add, the page says "Everything is already on the
   launcher".
8. **Tile options:** a new own page **Tile options** (title = the tile's name) with
   **Cancel** (selected first), **Move**, **Remove**. Ways to open it:
   - **Menu or F2** (until now these picked a tile up),
   - **holding Enter** (`LONG_PRESS`; until now this also picked a tile up),
   - **right-click** (a `gtk::GestureClick` for button 3 on each tile).
   **Move** goes back to the row with that tile picked up: the existing
   `pick_up` / `move_picked` / `drop_picked` / `cancel_picked` flow, unchanged apart from
   2D movement (below). **Remove** opens a confirmation, `Confirmable::RemoveTile`
   ("Remove <name>?", Cancel first, "It can be added back with +"), and on confirm
   updates `tiles.json` and rebuilds the page. Applies to the main row and submenus. The
   power menu, Add page and confirmations have no tile options. Removing a submenu's
   opener tile just hides it; the submenu stays in the config.
9. **Wrapping grid:** replace the single `gtk::Box` row per page with a `gtk::Grid`, and
   `row_layout(width, count)` with a pure
   `grid_layout(width, height, count) -> (tile_size, spacing, columns)`:
   - prefer `TILE_MAX` tiles at `TILE_SPACING`, as many columns as fit the width;
   - rows = ceil(count / columns); if those rows don't fit the available height, shrink
     the tile size (more columns per row) until they do. Never scroll, never overflow;
     tile size ≥ 1, never divide by zero (keep the existing guard tests' spirit).
   - The page keeps its buttons in a `Vec` in display order. A `relayout` function
     re-attaches them at `(i % columns, i / columns)` whenever the size, the order or the
     tile set changes. `fit_tiles` gets the height too (`surface.connect_layout` already
     supplies it).
   - Moving a picked-up tile: ← → one place (continuing across row ends), ↑ ↓ one row
     (± columns, clamped to the ends). `order::step` already takes a delta.
   - Focus: Up from the top row selects "+" (today line ~677 sends Up from anywhere on
     the main page to the power button). Up and Down within the grid use GTK's default
     direction-based focus. Down from "+" or power returns to the first tile. Check that
     Up/Down from a lower row still lands in the same column.

## Files

- `src/config.rs`: add `browser: Option<String>` to `Config`, add `"browser"` to `KEYS`,
  add a string check in `locate`. Tests: accepted, wrong type named, unknown key still
  refused.
- `src/catalog.rs` (new): the list; `find(id)`; tests that ids are unique, URLs are
  `https://`, and every icon resolves.
- `src/webapp.rs` (new): profile preparation and the command line, pure where possible
  (lock-host parsing, argument list). Tests mirror the vexos-nix behaviour.
- `src/tiles.rs` (new, modelled on `order.rs`): `Shown { added, hidden }`, `load`,
  `save`, plus pure `visible(page, configured, catalog, state)` and `addable(...)`.
  Tests as in `order.rs`: corrupt file → empty, stale ids ignored, name clash excluded,
  re-add restores.
- `src/order.rs`: no format change. `--print-order` (`order_listing` in `window.rs`)
  should show added and hide hidden tiles, so it matches the screen.
- `src/window.rs`: `Command::Web(&'static catalog::App)`, `Command::Add(..)`,
  `Command::Remove`, `Command::Move`; `Page::Add`, `Page::TileOptions`,
  `Confirmable::RemoveTile`, plus their `key()`/`from_key` strings (new, so no saved
  files break); the "+" button; options triggers replacing pick-up on Menu/F2/long-press;
  the grid; `rebuild` also rebuilds after add/remove. The empty main row's text becomes
  "No tiles yet — press + to add some".
- `src/main.rs`: `mod` lines only.
- `data/style.css`: "+" button, grid spacing if needed.
- Icons: catalog logos. **First check the licence** of the icon source vexos-nix already
  uses (homarr-labs/dashboard-icons, selfhst/icons; both pinned by commit in
  `modules/htpc-theater.nix`). If it allows redistribution, commit the SVGs under
  `data/catalog/` and add them to `data/io.github.vextheater.gresource.xml`, so dev runs
  show them. Otherwise fetch them pinned in `nix/package.nix` into
  `$out/share/vextheater/catalog/` and accept placeholders in dev runs. Logos that
  render black on the dark theme need a white fill (see `appleTvIcon` in vexos-nix).
- `nix/module.nix`: no new option needed (`settings.browser` passes through and is
  checked by `--check-config`).
- `README.md`: rewrite "Arranging tiles" as "Arranging, adding and removing tiles"
  (options page, "+", `tiles.json`, CEC note), document `browser` and the catalog list,
  and update the "Tiles shrink…" paragraph to the wrapping rule.

## Checks on the device

- Each catalog service plays DRM video in Brave (Widevine L3). Some services cap the
  resolution on Linux; note any that refuse the browser.
- Options and "+" with the actual remote. The HDMI-CEC bridge sends no Menu key (see
  below), so until vexos-nix maps one, opening tile options over CEC is not possible.
  Holding a key doesn't work over CEC either. "+" works over CEC.
